# R19-theme-inline: the theme script in the page, five requests before first paint

**Paul, 2026-10-12**, asked whether the theme script should stay a sixth file before first paint or go into the page: *"Inline the script."* Today `public/theme.js` (1,193 bytes: light or dark before the first paint, and the iOS viewport line) is hashed by the build into `assets/theme-<hash>.js` and named by every page with `<script src>`, so a cold visit asks for six files before it paints where the build-shape directive (r19-build-shape) wanted five. Its own comment says it is a file "so the site's Content-Security-Policy allows no inline script at all"; but the policy already allows the apps' page scripts by their hashes (`{{scripts}}` in `public/_headers`, filled by `scripts/headers.ts`; `scripts/check-build.ts` already checks every inline script of a built page against the policy and `version.json`), so an inline script with its hash in the policy is the same mechanism, not a new one. This overrides r19-build-shape's "no inlining of CSS or JS into the HTML" for this one script, and nothing else: the pages grow by the script's bytes (about 1.2 KB, under 1 KB gzipped) and stay `no-cache`.

## The design

- **The script lives in the shell.** The two functions of `public/theme.js` move into `index.html` as one inline `<script>` where the `<script src="./theme.js">` is now, comments kept. `public/theme.js` is deleted, `hashTheme` in `scripts/seo.ts` goes with it, and `dev/text.html` carries the same script inline (it is the dev page's; if it has no need of the theme, drop its script tag and say so). One source: the shell. Vite leaves a classic inline script as written; check that the built page's bytes are the shell's (the hash must be of what the browser sees).
- **The policy and version.json name its hash.** In `vite.config.ts`'s `closeBundle`, the hashes written into `_headers` and `version.json` are the page scripts' and every inline script of the built pages (read from `dist/index.html` after `writePages`, with the same regex `scripts/check-build.ts` uses: share it from one place, so the two never disagree). `scripts/check-build.ts` then passes as it stands.
- **The shape.** `scripts/budgets.ts` (`shapeOf`, the wanted list) and `scripts/sw-manifest.ts` (the worker's install list) drop the theme script; `budgets.json`: `requests` 5, `files` 111, and the comment's account of the thirty extra files and the request budget brought to the truth ("five, as the design says"). `e2e/smoke.spec.ts`: at most five before first paint and the header's sentence; the `arrayContaining` drops the theme file. `e2e/a11y.spec.ts`'s and `e2e/smoke.spec.ts`'s comments name "the theme script in the page" instead of `theme.js`; `src/kit/ui/theme.ts`'s comment too.
- **The words.** `scripts/network-doc.ts` line about what the worker keeps (and `docs/network.md`, regenerated by its script, never edited by hand), `public/_headers`'s comment, `docs/threat-model.md` or any other doc that says the site carries no inline script: grep `docs/` (not `docs/history`), `public/`, `scripts/` and `src/` for `theme.js`, `theme script` and `inline script` and bring every sentence to the truth: the policy allows the page scripts and the theme script by hash, and no other inline script.

## Proof

- `test/seo.test.ts`: the build's shell test becomes: every page (the home page, each app's, the embed page) carries the inline theme script, byte for byte the shell's; no `theme.js` and no `assets/theme-*` in the build; the test's own `build()` no longer copies `public/theme.js`.
- `test/check-build.test.ts` as it stands (it already tests an inline script without its hash) plus one case: the real shell's inline script hashed into the policy passes.
- A test on the real build (`test/build.test.ts` or where `dist/` is tested): `_headers`'s `script-src` and `version.json`'s `csp.scripts` both hold the hash of the shell's inline script, computed in the test from `dist/index.html`.
- `scripts/budgets.ts` with the new counts and `npm run build` green; `scripts/reproducible.ts` still byte-identical twice; the smoke run `PW_PORT=4290 npx playwright test e2e/smoke.spec.ts` with five before first paint on every page; `e2e/offline.spec.ts` and `test/sw.test.ts` green with the worker's shorter list.
- `npx vitest run`, `npm run lint`, `npm run build`, and `node scripts/check-build.ts` on the build, all green; the report says the home page's size before and after, and the request count before first paint from the smoke run.

## Not this

- No other inline script or style; no change to the pages' `no-cache`; no change to the script's behaviour (the theme choice and the iOS viewport line stay as they are). No change to the fonts' preloads. `docs/history/` untouched.
