# R19-first-paint: the page looks like itself before the app arrives

**Paul, 2026-10-12:** *"What can we do about fouc"*, and on the answer, *"Do both fixes."* Measured on the live home page (v1.2.2) at 390 wide over a 1.5 Mbps line with 150 ms latency, in Chromium: the first paint comes at 1.2 s, with the stylesheet (it is in the head and blocks the paint, so nothing is ever drawn unstyled) and the theme already set; from then until 4.7 s, while the app file arrives, the page is the static header the build writes for crawlers (`<header id="to-first">`, `scripts/seo.ts`): the "Agents: …llms.txt…" paragraph first, then the title, then a default bulleted list of the ten app names; at 4.7 s the shell removes it (`src/kit/core/shell.ts` `document.getElementById('to-first')?.remove()`) and draws the home page, a jump; at 5.3 s the faces the app asked for arrive and the type swaps (`font-display: swap` on every face in `src/styles/fonts.css`; only Sans Regular and SemiBold are preloaded by `index.html`). On a fast line the same happens in a blink. Two fixes, one mechanism each.

## The design

- **The static header is the page it becomes.** In the stylesheet (which is there for the first paint), `#to-first` is drawn as the home page's first screen: the title as the wordmark (`.to-brand`'s rules in `src/kit/ui/chrome.ts`'s stylesheet, read once from a shared rule or custom properties, never a second copy of the numbers), the list as the app rows (`.to-app-open`'s height, inset and type, without the icons and the templates buttons), at the same positions the shell will draw them: the column's inset (`--to-col-inset-l`), the header's height (`--to-header-h`), the row's inset (`--to-row-inset`). An app's page likewise: the app's name as the title and its line under it where the editor's header and first words will sit; its templates' names, which are for crawlers, out of sight. The agents line stays first in the DOM for a fetcher and is hidden from sight (`.sr-only`, which the kit has). The shell's removal of the header stays as it is; the change is the look of what it removes. What the browser has to repaint when the app arrives is then the icons and the menu button, not a page.
- **The type does not jump when a face arrives.** Each `@font-face` in `src/styles/fonts.css` gets a size-adjusted local fallback: a second `@font-face` with the same family name and weight, `src: local(…)` naming the system faces (Arial and Helvetica for Sans, Georgia and Times for Serif, Menlo and Courier for Mono, and the `-apple-system`/Segoe faces the kit's stack names), with `size-adjust`, `ascent-override`, `descent-override` and `line-gap-override` worked out against Plex's metrics (the builder measures them with `fontkit` or `opentype.js` from the woff2 files in `public/fonts`, or by the browser: a test that types the same paragraph in Plex and in the fallback and compares the box's height and the line count), so the swap moves nothing. `font-display: swap` stays. The SemiBold Serif and the Mono Regular, which the home page and an app's first screen draw, join the preloads in `index.html` only if the smoke run's request budget (five before first paint, `budgets.json`) is kept: measure, and if a preload would be a sixth request, leave it and say so.
- **Not a spinner, not a blank.** Nothing is hidden until the app arrives, and nothing says "loading".

## Proof

- `test/seo.test.ts` or a new `test/browser/first-paint.test.ts`: the static header of the built home page, given only the stylesheet (no module), measured against the home page the shell draws at 390 and 1100 wide: the title's text box and each app row's name box within two pixels of the same positions; the agents line not visible (`offsetParent` null or `sr-only`). The same for one app's page (the Word Processor's).
- Layout shift: in the Playwright smoke run on the built site (`e2e/smoke.spec.ts`, Chromium, where `layout-shift` entries are reported), with the network throttled through CDP to 1.5 Mbps and 150 ms, the sum of `layout-shift` values from the first paint through the shell's mount and the faces' arrival is under 0.05 on the home page and on the Word Processor's page; the spec says what it measured.
- The fallback faces: a browser test that a paragraph set in the fallback (the Plex faces blocked: `document.fonts` not loaded, or the family name pointed at the local face alone) is within one line of the same paragraph in Plex, and its block's height within 3%.
- `npm run build` within budgets (the stylesheet's budget may need its few hundred bytes: raise it in `budgets.json` with the reason in the commit), the smoke run's five requests before first paint, `npx vitest run`, `npm run lint`.

## Not this

- No splitting of the app file, no second stylesheet, no inline CSS, no skeleton boxes or placeholders that are not the page's own words. No change to what the static header says to a crawler.
