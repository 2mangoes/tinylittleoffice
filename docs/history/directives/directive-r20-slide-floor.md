# R20-slide-floor: a slide on a phone holds its words

**Paul, 2026-10-13, on an iPhone, a deck whose every slide the measures said fits:** *"For the first time ever the bullets in that deck are too big and run into the bottom border of the deck, maybe the theme."* Measured in the browser at 390px wide (a test, not an eye): the layout chose 26px body type for a slide of five bullets (`layoutSlide`, 960 by 600), which the canvas maps to 2.71cqw, 10.6px on that phone; the canvas's rule `font-size: max(1rem, var(--deck-body))` (`src/apps/deck/style.css`) raised it to 20.8px, twice the layout's size; every bullet wrapped to two lines; the words ran 121px past the bottom of a canvas that stayed 390 by 244, `aspect-ratio` holding and `overflow: hidden` cutting them, the theme's bottom rule across them. The stylesheet's own comment beside `.deck-words-row` says the canvas was to grow "rather than hide them": it never has, since the automatic minimum height of an aspect-ratio box applies only when its overflow is visible (css-sizing-4 §7.4). The rail's thumbnails are right (they draw the layout's SVG); the editing canvas is not.

The floor itself stays: a box of words under 16px makes iOS zoom the page on focus, and the phone test holds "every box is 16px or more". What changes is that the layout knows about it.

## The design

- **The layout takes the floor.** `layoutSlide(s, { w, h, loud, floor })` in `src/apps/deck/view.ts` gains `floor`, the smallest type the screen allows in the page's own units (0 by default: nothing changes for the measures, the SVG, the show, the exports, the rail). With a floor, every size list the layout tries (`sz([...])` for titles, bodies, notes, the icon slide's sub-line) is clamped so no size is below it, the words are fitted at those sizes, and `fit.body.over` says how far they still run past the box. The editor lays the slide out twice when the floor bites: once on 960 by 600 to learn `over`, then on 960 by `600 + over` (a taller page, "a tall page gets more rows, not bigger type", as the layout says of itself), which fits.
- **The canvas is as tall as its words.** `canvasStyle` in `src/apps/deck/editor.ts` sets `--deck-h` to the page height the layout fitted on, so `aspect-ratio: var(--deck-w) / var(--deck-h)` makes the canvas exactly tall enough; nothing is cut, nothing overflows, no CSS grows anything. The editor learns the floor from a `ResizeObserver` on the canvas (its width in px) and the root's font size: `floor = remPx * 960 / canvasPx`, recomputed when either changes (a phone turned, the size stepper). `--deck-body` and `--deck-title` are the layout's sizes as now (they are at or above the floor by construction); the `max(1rem, …)` in the stylesheet stays as the belt to this brace.
- **The decoration is drawn for the page it is on.** Each theme's `deco` in `src/apps/deck/theme.ts` becomes a function of the page, `deco(w, h)`, returning the SVG for that size: Ivory's rules at `y=30` and `y=h-32`; Graphite's underline at `h-36`; Ocean's waves at `h-34` and `h-18`; Arcade's stripes at `h-38`, `h-26`, `h-14`; Chalkboard's frame `h-12` tall; Boardroom's bar `h` tall; Sunset's and Bubblegum's corner circles at the corners of that page; Confetti scattered over it; Midnight's square at the top right as now. `deco(960, 600)` returns byte for byte what the string was (a test over every theme). The canvas's background SVG is built with `viewBox="0 0 ${w} ${h}"` and the layout's page, and `pageSvg`'s two uses in view.ts (a page and the closing slide) pass theirs, so a poster or a booklet page wears its theme undistorted rather than stretched. The comment at `.deck-words-row` is brought to what is true.
- **The thumbnails and the show do not change.** The rail draws the 960 by 600 layout, which is the slide as it will be presented and printed; the show scales that page to the screen. Only the editing canvas grows, and only where the floor bites. `measureDeck` and `lintDeck` do not change: the measures are the 960 by 600 truth, and a slide that fits there fits.

## Proof

- `src/apps/deck/tests/view.unit.test.ts` (node): `layoutSlide` with `floor: 51` on a slide of five long bullets sets the body at 51, reports `over` > 0 at 600 tall, and fits at `600 + over`; with no floor the same slide fits at 26 with `over` 0; every theme's `deco(960, 600)` equals its former string; Ivory's `deco(960, 900)` puts the second rule at `y="868"`.
- `src/apps/deck/tests/editor.test.ts` (browser), at 390 by 844 with the five-bullet slide quoted above in the Ivory theme: the body's computed font size is at least 1rem; the canvas is taller than 16:10; the last bullet's bottom edge lies above the canvas's padding edge; the deco in `--deck-deco` names the taller page (its viewBox height equals `--deck-h`), and the bottom rule sits at `h-32`, inside the padding. At 1100 by 800 with the same slide the canvas is 16:10 and the body's size is the layout's 26px scaled. The phone test "every box is 16px or more" still green.
- `npm run lint`, `npx vitest run`, `npm run build`; the e2e keyboard and smoke specs.

## Not this

- No change to the measures, the lint, the SVG of a slide, the show, the PowerPoint or the PDF. No hidden words, no scrolling inside a slide, no smaller floor. No change to the rail.
