# R19-build-shape: one file, fetched once, kept for offline

**Paul, 2026-10-12:** *"Why are there 305 files? I thought we did a minimized production build."* It is minified (the first load 225 KB gzipped, every chunk inside its budget) but split into 305 files: 140 app chunks, among them about forty that hold one icon each and three per app; a second complete build of the parsing API (`dist/api`, 114 files, 5 MB) with its own copies of the editors; 15 fonts and 10 cards, which are right; 26 pages and files, which are right. The home page's first paint pulls 37 files. **Paul, 2026-10-12:** *"This whole app should be a gzipped set of files. We should have as few network round trips as possible."* The edge already serves every file compressed (Brotli or gzip by the browser's `accept-encoding`); the round trips are the build's shape to fix.

**Paul, 2026-10-12, deciding:** *"Does it really matter at this scale? Shouldn't we just package the whole thing up and avoid hitting the server after that?"* Measured on the v1.0.4 build, gzipped: the app with its English strings, the icon library, the math engine and the emoji data in one file is 727 KB; the eighteen other languages are 746 KB more; the app alone without the three libraries would be 430 KB. Paul chose the one file, then (*"download the apps and home language and emoji and icons but leave out the templates and other languages unless needed"*) the shape below, and offline through a service worker tied to Save in browser (*"Then offline is instant"*). Measured: the one file without the templates and the other languages is 669 KB gzipped; the ten templates files together 58 KB; the pages' HTML 3 KB.

## The design

- **One file is the app.** `vite.config.ts` builds a single module, `app-<hash>.js`, holding the kit, every app's editor, commands and view, the English strings, the icon library, the emoji data and the math engine: no code splitting among those, no dynamic import inside it (a dynamic import that stays becomes a static one). Every page's HTML names it with one `modulepreload` and one `<script type="module">`; the stylesheet is one file named with a `preload`.
- **What stays a file of its own, fetched only when needed**, each kept a year once fetched: an app's templates (one file per app, `templates-<id>-<hash>.js`, fetched when its templates are opened, as the lazy templates do now; the Blank document needs none); the eighteen languages other than English (one file each, fetched before the first paint of a page a link or the browser names in that language); the fonts by `unicode-range`, as now; the share cards and icons. Nothing else: the single-icon chunks, the per-app chunks and the preload helper go.
- **Fetched once, kept a year.** The app file, the stylesheet, the templates, the languages and the fonts carry `Cache-Control: public, max-age=31536000, immutable` and a content hash in their names, as now; the test that reads `public/_headers` holds it. The HTML pages stay `no-cache`.
- **Offline, through Save in browser.** A service worker, `src/sw.ts` built to `dist/sw.js`, registered by the kit when Save in browser is turned on or is on at load, and unregistered with its caches deleted when it is turned off (the switch's sentence, 'Turn off to remove all files and settings', already says so; the drawer's words do not change). Private visits register nothing, as the test `test/browser/no-service-worker.test.ts` holds today for everyone; that test becomes: nothing under Private, the registration under Saved, and nothing left after Saved is turned off. What the worker keeps: on install, the eleven pages' HTML, the app file, the stylesheet, the manifest and icons, and the Latin faces (Sans and Serif, regular and semibold, and Mono); on fetch, any same-origin file with a hash in its name that the page asks for, so a templates file, a language or a script's fonts are kept once used. Pages are served network first with the cached copy when the network fails, so an online visit is never stale; hashed files are served from the cache first, since a hash never changes meaning. The worker's own file carries the build's hash list (`scripts/sw-manifest.ts`, run by the build), so a new deploy changes `sw.js`, the browser installs the new one on the next online visit and it drops the old caches on activation. The worker never stores a document: the pages carry none and the document is after the `#`, which never reaches it. The network page and `docs/privacy.md` say what the worker keeps and when; `src/kit/network.ts` gains `sw.js` as an entry.
- **The API build is the parser.** `vite.api.config.ts` builds `api.js` as one file from `src/api.ts` with the kernel, the drawing code (no DOM) and each app's definition, templates and view; never an editor, never the chrome, never the icon picker. Where a definition reaches its editor by an import, the API build marks the editor external or the definition is split so the API imports the half without it (one mechanism; say which in the report). `dist/api/` is that one file, within the budget r18-agent-fast set.
- **The budgets say so.** `budgets.json` names the one app file's gzipped size (669 KB measured; set 700 KB), the stylesheet, each language file, and two counts: files in `dist/` (at most 80: eleven pages, the app, the stylesheet, ten templates files, eighteen languages, the worker, the API, fourteen fonts, ten cards, the manifest and icons, robots, the LLM files, version.json) and requests before first paint on any page (at most 5: the HTML, the app, the stylesheet, two Latin faces; one more on a page in another language). `scripts/budgets.ts` checks all of it and the build fails over budget.
- **First paint is not slower than it needs to be** for the bytes: the HTML names the app file and the stylesheet in its head so both are asked for the instant it arrives; the two Latin faces are preloaded; the page's static HTML (r18-seo's real text) shows while the module arrives.

## Proof

- `scripts/budgets.ts` with the counts; `npm run build` green; `scripts/reproducible.ts` still byte-identical twice.
- `test/build.test.ts` (or where the build is tested): `dist/assets` holds one app file, one stylesheet, ten templates files and eighteen language files and nothing else; the app file contains no `import(` but the two that reach a templates file and a language file; `dist/api` is one file with no editor code (a grep for `customElements.define` and `LitElement` finds nothing there); every page's HTML names the app file and the stylesheet in its head.
- The e2e smoke run on the built site: the home page and each app open; from Playwright's request log, the requests before first paint number at most five, every one initiated by the HTML; a second page of the same site in the same context fetches only its HTML (every other request served from cache); a page in French fetches its HTML and the French file.
- `test/browser/sw.test.ts` (browser-alone, since it registers a worker): under Saved the worker registers and its cache lists the pages, the app file and the stylesheet; a fetched templates file joins the cache; turned off, no registration and no cache remains; under Private nothing registers. `e2e/offline.spec.ts`: a page visited under Saved, then the context set offline, opens again and a template file fetched before is there; one not fetched before is not, and the app says so in a sentence rather than failing silently.
- `docs/dependencies.md` and the network page with `sw.js`; the sizes in the report before and after (bytes gzipped per chunk, file counts).

## Not this

- No worker under Private; no document in any cache; no inlining of CSS or JS into the HTML (the pages must stay small and `no-cache`). No change to the fonts or the cards. The languages stay separate files: 746 KB more on every first visit for strings in seventeen languages the person will not read.
